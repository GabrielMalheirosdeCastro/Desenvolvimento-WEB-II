# Plano de Ação — v1.15.0: Qualidade e Testes Automatizados (Vitest · supertest · cobertura ≥ 80%)

**Data:** 2026-06-15
**Solicitado por:** Gabriel Malheiros de Castro
**Contexto:** Segunda versão da fase "robustez primeiro". A v1.13.0 já entregou **E3/E4** (Playwright na
estação) e **E5** (gate de CI), além de deixar **E1 parcial** (`npm test` agrega os testes core
headless). Esta versão **formaliza** a suíte de testes para atingir o RNF de cobertura, fechando o
Bloco E e o **D3/RNF08**.

## Objetivo

- **E1** — Migrar a verificação atual (`scripts/test-*.mjs`) para **Vitest** formal, com estrutura de
  testes unitários da lógica da API (`auth.js`, `chatbot.js`, helpers de `routes.js`).
- **E2** — Adicionar **testes de integração API/DB** com `supertest` (rotas autenticadas, guardas
  anti-IDOR, contratos `source: db`).
- **D3/RNF08** — Atingir **cobertura ≥ 80%** na camada de API, com relatório de cobertura no CI.

## Etapas

### Bloco E1 — Vitest (unitários)
- [ ] 1. Adicionar `vitest` + `@vitest/coverage-v8` como devDependency (raiz ou `apps/api`).
- [ ] 2. Criar `vitest.config.ts` com `coverage` (provider v8, thresholds 80%) e ambiente `node`.
- [ ] 3. Portar `test-auth-core.mjs` e `test-chatbot-core.mjs` para specs Vitest (`*.test.ts`/`.mjs`).
- [ ] 4. Cobrir lógica pura: hashing/JWT (`auth.js`), motor curado do chatbot (`chatbot.js`),
      cálculo de resultado de bem-estar, `RANK()`/serializações em helpers de `routes.js`.
- [ ] 5. Atualizar o script `npm test` para `vitest run --coverage`.

### Bloco E2 — supertest (integração API/DB)
- [ ] 6. Adicionar `supertest`; criar harness que sobe o app Express sem `listen` fixo (porta efêmera).
- [ ] 7. Testes de guardas: rota protegida sem cookie → 401; papel insuficiente → 403 (RBAC A4).
- [ ] 8. Testes de contrato: endpoints `/api/*` retornando `source: db` com banco de teste populado.
- [ ] 9. Testes anti-IDOR: usuário A não acessa/edita recurso de usuário B (`req.usuario.sub`).
- [ ] 10. Estratégia de banco de teste: SQLite/Postgres efêmero ou transação com rollback por teste.

### Bloco D3 — Cobertura ≥ 80%
- [ ] 11. Rodar `vitest run --coverage` e identificar arquivos abaixo do limiar.
- [ ] 12. Completar testes até `lines/branches/functions ≥ 80%` na camada de API.
- [ ] 13. Gerar badge/resumo de cobertura no `README.md`.

### CI + Encerramento
- [ ] 14. Atualizar `.github/workflows/deploy.yml`: job `test` roda `vitest run --coverage` (já é gate).
- [ ] 15. Bump v1.15.0 (3× `package.json`), `CHANGELOG.md`, `README.md`, badge na página.
- [ ] 16. Commits atômicos pt-BR → push → `node scripts/deploy.mjs` → validar `/version` = 1.15.0.

## Impacto Esperado

- Arquivos afetados: `vitest.config.ts` (novo), `tests/unit/**` e `tests/integration/**` (novos),
  `package.json` (script `test` + devDeps), `.github/workflows/deploy.yml`, `README.md`, `CHANGELOG.md`.
- Pendências fechadas: E1, E2, D3/RNF08. (E3/E4/E5 já entregues na v1.13.0.)
- README/CHANGELOG precisam ser atualizados? **Sim.**

## Riscos e Cuidados

- Banco de teste **não pode** apontar para produção — usar instância efêmera/transação isolada para
  não poluir o Postgres da VPS.
- O gate de CI já existe (`needs: test`); migrar para Vitest **não pode** quebrar o pipeline — validar
  localmente antes do push.
- E3 (E2E Playwright completo) permanece fora deste MINOR — roda só na estação (VPS headless), fica
  para a v2.0.0.
- Não inflar cobertura com testes triviais sem asserção real — medir branches, não só linhas.

## Critério de Conclusão

`npm test` executa Vitest com cobertura ≥ 80% na API, testes de integração `supertest` verdes, CI
bloqueando deploy em falha, `/version` = **1.15.0**, e E1/E2/D3 marcados ✅ no backlog.
