# Plano de Ação — v1.8.0 Fórum (H6/RF08) + Biblioteca (H7/RF06-07)

**Data:** 2026-06-14
**Solicitado por:** Gabriel Malheiros de Castro
**Contexto:** Fase 3 da varredura de mocks ("nada é mock"). As telas de **Fórum**
(`/dashboard/forum`) e **Biblioteca** (`/dashboard/biblioteca`) ainda exibem dados estáticos e
têm botões inertes ("+ Novo Tópico", "Iniciar Trilha", "Acessar Recurso", "Sugerir Recurso").
O schema já modela as tabelas necessárias; falta criar endpoints e ligar a UI.

> **Pré-requisito:** a v1.7.1 (hotfix da Mentoria) deve estar publicada antes de iniciar esta fase,
> para não acumular um bug de produção conhecido sob novas mudanças.

## Objetivo

Tornar reais (com persistência no Postgres de produção) as telas de Fórum e Biblioteca,
publicando como **v1.8.0**, mantendo o padrão aditivo e anti-IDOR já consolidado em `/api/metas`
e `/api/bem-estar`.

## Tabelas disponíveis (schema confirmado)

- **Fórum:** `foruns_discussao` (id, criado_por, titulo, descricao, categoria, created_at) ·
  `forum_posts` (id, forum_id, usuario_id, conteudo, votos_positivos, created_at) ·
  `forum_comentarios` (id, post_id, usuario_id, conteudo, status, created_at, deleted_at).
- **Biblioteca:** `recursos` (id, titulo, descricao, tipo, url, categoria, visualizacoes) ·
  `trilhas_aprendizagem` (id, nome, descricao, publico_alvo) · `trilha_recursos` (ordem) ·
  `usuario_recursos` (id, usuario_id, recurso_id, data_acesso, favorito, UNIQUE(usuario_id,recurso_id)).

> **Modelo do Fórum:** um "tópico" da UI mapeia para uma linha de `foruns_discussao`. Comentários
> mapeiam para `forum_comentarios` (via `forum_posts`). Para o MINOR, o escopo é criar/listar
> **tópicos**; comentários ficam como leitura (criação de comentário fica para iteração futura,
> registrada como limitação).

## Escopo por item

### H6 — Fórum funcional (RF08)
- **Backend (rotas ADITIVAS no fim de `apps/api/routes.js`, padrão `/api/metas`):**
  - `GET /api/forum` (público ou `requireAuth` — alinhar com `/api/eventos`, que é público):
    lista `foruns_discussao` (com contagem de posts/categoria) ordenado por `created_at DESC`.
    Fallback de UI quando vazio; 503 se `!isConnected()`.
  - `POST /api/forum` (`requireAuth`): cria tópico (`titulo`, `descricao`, `categoria`),
    `criado_por = req.usuario.sub`. Validação de entrada (titulo obrigatório, limites de tamanho).
  - (Opcional) `GET /api/forum/:id` com posts/comentários do tópico.
- **Frontend (`ForumPage.tsx`):** substituir a lista mock por `GET /api/forum` (estados
  loading/empty/error). Botão "+ Novo Tópico" abre formulário (modal/seção) → `POST /api/forum`
  com `credentials: "include"` → recarrega a lista. Filtro por categoria client-side.

### H7 — Biblioteca funcional (RF06/07)
- **Backend (rotas ADITIVAS):**
  - `GET /api/recursos` (público, espelhando `/api/eventos`): lista `recursos`
    (titulo, tipo, url, categoria, visualizacoes). Já pode existir parcialmente — verificar.
  - `GET /api/trilhas`: lista `trilhas_aprendizagem` (+ contagem de recursos via `trilha_recursos`).
  - `POST /api/recursos/:id/acesso` (`requireAuth`): registra acesso em `usuario_recursos`
    (UPSERT por `UNIQUE(usuario_id, recurso_id)`, atualiza `data_acesso`); opcional incrementar
    `recursos.visualizacoes`. Anti-IDOR via `req.usuario.sub`.
  - (Opcional) `POST /api/recursos/sugestao` (`requireAuth`): grava sugestão do usuário.
- **Frontend (`LibraryPage.tsx`):** ligar "Iniciar Trilha" (navega/expande a trilha real),
  "Acessar Recurso" (`POST .../acesso` + abre `url` em nova aba), "Sugerir Recurso" (form →
  endpoint). Adicionar `credentials: "include"` às chamadas autenticadas. Estados de UI.

## Riscos e Cuidados

- **Verificar ReferenceError de runtime** navegando cada tela antes do deploy (regressão da v1.7.0
  ensinou que `get_errors` não basta). Garantir imports de todos os componentes usados.
- **Modelo de Fórum em 3 tabelas**: não tentar implementar comentários completos neste MINOR;
  escopar a criação de tópicos para evitar complexidade e quebra.
- **`/api/recursos`/`/api/eventos` públicos**: manter consistência de auth (leitura pública,
  escrita autenticada) para não quebrar `credentials`.
- **`dist/` versionado** + **corrida de deploy**: rebuild antes do commit; um único redeploy.
- **Idempotência do seed** (se usado): `deleteMany`+`create` escopado, nunca apagar dados reais.
