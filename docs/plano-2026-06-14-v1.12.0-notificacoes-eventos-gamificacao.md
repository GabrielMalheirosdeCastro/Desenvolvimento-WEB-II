# Plano de Ação — v1.12.0 (Notificações, Eventos e Gamificação)

**Data:** 2026-06-14
**Solicitado por:** Gabriel Malheiros de Castro
**Contexto:** Com a v1.11.0 publicada (Chatbot RF16), seguimos no roadmap
([plano-2026-06-14-roadmap-versoes-finais.md](plano-2026-06-14-roadmap-versoes-finais.md))
para a **v1.12.0**, que fecha três pendências 🟨 do backlog: **B5/RF10** (Notificações),
**B6/RF12** (Eventos) e **B7/RF13** (Gamificação). As três já têm schema e UI parciais — o
esforço é endpoint + UI, sem migração de banco.

## Objetivo

Tornar reais (deixar de ser mock estático) os três recursos, mantendo o padrão arquitetural
vigente: rotas **aditivas** ao final de `routes.js`, `query()` parametrizado, contrato
`source: db|fallback`, `requireAuth` + escopo `usuario_id = req.usuario.sub` (anti-IDOR),
resiliência a banco indisponível e telas com estados loading/empty/error.

## Etapas

- [ ] 1. **Backend — Notificações (RF10)**: `GET /api/notificacoes` (lista do usuário + contagem
  de não lidas), `POST /api/notificacoes/:id/marcar-lida` e `POST /api/notificacoes/marcar-todas-lidas`.
  Todas `requireAuth` + anti-IDOR.
- [ ] 2. **Backend — Eventos (RF12)**: `POST /api/eventos/:id/inscrever` (valida evento, UPSERT
  `usuario_eventos` ON CONFLICT, anti-IDOR) e `GET /api/eventos/minhas` (inscrições do usuário).
- [ ] 3. **Backend — Gamificação (RF13)**: `GET /api/gamificacao/perfil` (pontos, streak, posição,
  conquistas com flag `earned`, histórico derivado das conquistas) e `GET /api/gamificacao/ranking`
  (top alunos por `pontos_totais`, com nome reduzido para privacidade e marcação do usuário atual).
- [ ] 4. **Frontend — NotificationBell**: substituir o mock por `fetch('/api/notificacoes')` com
  `credentials: include`; marcar lida/todas persiste no backend; degrada para vazio se 401/erro.
- [ ] 5. **Frontend — EventsPage dedicada**: nova tela `/dashboard/eventos` (separa eventos da
  Biblioteca), com inscrição funcional ("Inscrever-se" → POST, estado "Inscrito"). Rota + item de
  menu "Eventos".
- [ ] 6. **Frontend — LibraryPage**: remover a aba de Eventos (agora dedicada), deixando a
  Biblioteca focada em recursos/trilhas.
- [ ] 7. **Frontend — ProfilePage**: ligar pontuação/estatísticas/conquistas/histórico ao
  `GET /api/gamificacao/perfil` real; adicionar seção **Ranking entre alunos**
  (`GET /api/gamificacao/ranking`). Degrada para placeholders se indisponível.
- [ ] 8. **Seed** (`seed-prod.sql`): notificações da persona (idempotente) e algumas linhas de
  `gamificacao` para que o ranking não fique com uma única entrada.
- [ ] 9. **Release**: bump 1.11.0 → **1.12.0** (3 `package.json`), `CHANGELOG` `[Unreleased]` →
  `[1.12.0]`, backlog (B5/B6/B7 → ✅), build da SPA, bateria de testes, commit atômico pt-BR.
- [ ] 10. **Deploy + validação**: push `master`, deploy único limpo, `curl /version == 1.12.0`,
  `/healthz`, validação visual via Playwright MCP (sino, eventos, ranking).

## Riscos e Cuidados

- **Anti-IDOR:** toda leitura/escrita de notificações e inscrições escopada a `req.usuario.sub`.
- **Privacidade do ranking:** expor nome reduzido (primeiro nome + inicial), nunca matrícula/e-mail.
- **Resiliência:** endpoints sempre com fallback; a UI nunca quebra se o banco cair.
- **Não quebrar a Biblioteca:** ao remover a aba de eventos, revisar imports/estado órfãos.
- **Seed em produção** toca dados reais — aplicar via SSH (chave já autorizada) e validar contagem.
