# Plano de Ação — v1.18.0: Acessibilidade WCAG 2.1 AA + Dark Mode por Tokens

**Data:** 2026-06-16
**Solicitado por:** Gabriel Malheiros de Castro
**Contexto:** Fecha o item **D2/RNF04** (hoje 🟨, baseline na v1.14.0) e conclui a pendência visual do
**H9** (dark mode "parcial" da v1.7.0). Causa-raiz já diagnosticada: o `ThemeContext` e os tokens CSS
funcionam, mas ~6 telas usam **cores hex hardcoded sem variante `dark:`**, ignorando os tokens.

## Objetivo

Tornar o dark mode **visualmente completo** em todas as superfícies e atingir conformidade
**WCAG 2.1 AA** (contraste, foco, leitor de tela), substituindo cores hardcoded por **design tokens já
existentes** — sem inventar tokens novos onde não é necessário e sem remover nenhuma marcação de
acessibilidade já entregue (v1.14.0).

## Causa-raiz técnica (confirmada por varredura de código)

1. O tema funciona: `apps/web/src/app/theme/ThemeContext.tsx` aplica `.dark` no `<html>`, persiste em
   `localStorage["sa_tema"]` e reage a `prefers-color-scheme`.
2. Os tokens existem: `apps/web/src/styles/theme.css` define `--background`, `--foreground`,
   `--primary`, `--border`, `--ring` etc. para light **e** dark (Tailwind v4, `@theme inline` +
   `@custom-variant dark`).
3. Os componentes base `apps/web/src/app/components/ui/*` já são dark-ready.
4. **O problema** está nas páginas/layouts que escrevem `bg-[#003366] text-white` em vez de
   `bg-primary text-primary-foreground`. Além disso, `--input-background` não é redefinido no `.dark`.
