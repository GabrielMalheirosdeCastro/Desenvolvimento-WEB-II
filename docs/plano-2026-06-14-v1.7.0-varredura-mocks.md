# Plano de Ação — v1.7.0 Varredura de Mocks (H8/H9/H5/H4)

**Data:** 2026-06-14
**Solicitado por:** Gabriel Malheiros de Castro
**Contexto:** Após a entrega da Avaliação de Bem-estar (RF11 / v1.6.0), a Fase 2 do lote
("nada é mock") ataca telas que ainda exibem dados estáticos ou botões sem efeito. O objetivo
é reduzir a zero os mocks de escrita/identidade nas telas de Perfil, Mentoria e Concentração.

## Objetivo

Tornar reais (com persistência ou comportamento client-side coerente) as telas de Perfil
(identidade + tema), Mentoria (cadastro de mentor + lista) e Concentração (timer + respiração
guiada), publicando como **v1.7.0**.

## Escopo por item

### H8 — Perfil real (RF05)
- **Backend (rotas ADITIVAS no fim de `apps/api/routes.js`):**
  - `GET /api/usuario/perfil` (`requireAuth`): retorna nome, matrícula, e-mail, tipo, `e_mentor`
    e `data_nascimento` reais do usuário logado (escopo `WHERE id = req.usuario.sub`, anti-IDOR).
  - `PATCH /api/usuario/perfil` (`requireAuth`): atualiza `nome` e `email_institucional`.
    Re-emite o JWT + atualiza o cookie de sessão quando o e-mail muda (e-mail está no token).
    Trata violação de UNIQUE (e-mail duplicado → 409). Validação de entrada e 503 se `!isConnected()`.
- **Frontend (`ProfilePage.tsx`):** substitui a identidade hardcoded (nome/matrícula/e-mail) pelos
  dados reais (`useAuth()` + `GET /api/usuario/perfil`). Formulário de edição de nome + e-mail
  → `PATCH` → `recarregar()` do `AuthContext` + feedback de sucesso/erro. Estados loading/erro.
- **Fora de escopo:** gamificação (pontos, badges, estatísticas) = RF13, não faz parte deste lote.
  Esses cartões permanecem ilustrativos; não serão expandidos nem apresentados como persistidos.

### H9 — Tema persistido (RF05 / preferências)
- **`ThemeContext`** (claro/escuro/automático) persistido em `localStorage`, aplicando a classe
  `.dark` em `<html>` (com suporte a `prefers-color-scheme` no modo automático).
- Seletor de tema no `ProfilePage` ligado ao contexto (preferência sobrevive a reload).
- **Limitação técnica conhecida:** as páginas usam cores hex hardcoded (`#003366`) em vez dos
  design tokens (`var(--primary)`), então o efeito visual do dark mode é **parcial** (atinge só
  superfícies baseadas em token). Dark mode visual completo exigiria refatorar todos os
  componentes — adiado para fora deste MINOR. Esta entrega cobre a **persistência da preferência**.

### H5 — Mentoria funcional (RF09)
- **Frontend (`MentorshipPage.tsx`):**
  - Corrigir `fetch` do cadastro de mentor para incluir `credentials: "include"` (bug conhecido —
    quebra em rota protegida sem o cookie).
  - Hidratar o estado inicial `souMentor` a partir de `useAuth().usuario.eMentor`.
  - Ligar a lista de mentores ao `GET /api/mentorias?papel=mentor` real (com fallback de UI).
- **Backend:** `POST /api/mentorias/cadastro-mentor` já existe; ajustar para usar
  `req.usuario.sub` (em vez de `MATRICULA_PADRAO`) sob `requireAuth`, mantendo retorno `eMentor`.

### H4 — Concentração funcional (RF04)
- **Frontend (`ConcentrationPage.tsx`):** o timer Pomodoro já funciona. Tornar funcional o
  exercício de respiração guiada 4-7-8 (ciclo animado client-side com fases inspirar/segurar/
  expirar) acionado pelo botão "Iniciar Exercício Guiado". Sem backend.

  não deslogar o usuário. Tratar `UNIQUE` (e-mail já usado) com 409 explícito.
- **`dist/` versionado**: rebuild obrigatório da SPA antes do commit (Dockerfile copia pronto).
- **Corrida de deploy**: disparar apenas `deploy.mjs` (não acionar workflow + manual juntos).
- **Dark mode parcial**: comunicar a limitação; não prometer dark mode visual completo.
